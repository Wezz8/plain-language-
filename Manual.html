The Plain language

Plain is a dynamically typed programming language for readable programs. You write exact, small commands rather than unrestricted English. Version 1.0 includes reusable actions, structured data, modules, loops, exceptions, a standard library, and tests. The same interpreter runs in the offline Studio and in Node.js.

Your first program

set name to "Ada"
say "Hello,", name

repeat 3 times
  say "I made this."
end

Use one command per line. Commands and names are case-sensitive. Commands use lowercase. Blank lines are ignored. A comment starts with #, except inside quoted text. Indentation helps people read; the word end closes a block. Lists, records, function calls, and grouped expressions can span several lines inside brackets.

Values and names

set creates or changes a name. A name starts with an ASCII letter and can contain letters, digits, and underscores. Examples: score, first_name, player2. Language keywords cannot be names. A name must have a value before you read it. Names may hold different kinds of values at different times.

set score to 10
set score to score + 5
say score

Text uses double quotes. Escapes follow JSON rules, including \n, \r, \t, \", \\, and \uXXXX. Text positions count Unicode code points, so an emoji counts as one position; a combined grapheme can contain several code points. Text is immutable: create a new text value to change it.

Calculations and output

Use +, -, *, /, and %. % gives the remainder. Parentheses group calculations. + joins text when either side is text, and concatenates two lists. Other arithmetic needs numbers. Dividing by zero raises an error.

say 2 + 3 * 4
say (2 + 3) * 4
say 7 % 3
say "Score: " + 10
say "Score:", 10
say [1, 2] + [3]

say prints a line. Separate expressions with commas to place a space between them. To print a blank line, use say "". Lists and records have readable representations; use json.write when you need JSON instead.

Choices

if score is at least 80
  say "Excellent"
else if score is at least 50
  say "Passed"
else
  say "Try again"
end
ComparisonMeaning
a is bEqual values
a is not bDifferent values
a is more than bGreater than
a is less than bLess than
a is at least bGreater than or equal
a is at most bLess than or equal

Equality is strict: number 18 differs from text "18". Lists and records compare their contents recursively; record field order does not affect equality. Functions compare by identity. Ordering comparisons need numbers.

Combine conditions with not, and, and or. Conditions must be booleans. A number, text, or list is not implicitly true or false. and and or stop as soon as the result is known.

if age is at least 18 and age is less than 65
  say "In range"
end

From highest to lowest precedence: calls/fields/positions; unary + and -; * / %; + -; comparisons; not; and; or. Use parentheses to make complicated conditions clear. Chained comparisons such as 1 is less than age is less than 10 are invalid; combine two comparisons with and.

Lists and records

Lists preserve order. Positions start at 1. Reading or changing an invalid position raises an error. Record field names can be identifiers or quoted text. Missing fields raise an error; has and get let you handle optional fields.

set people to [
  {name: "Ada", score: 92},
  {name: "Sam", score: 78}
]

say people[1].name
set people[2].score to 85
add {name: "Jo", score: 90} to people
remove people[1]

set details to {"full name": "Ada Okafor"}
say details["full name"]
say get(details, "nickname", "No nickname yet")

add value to items appends one item. remove items[2] removes an item and shifts later positions left. remove person.name removes a field. Setting a new record field creates it. Setting a list position must use an existing position; use add to append.

Lists and records are shared by reference. set second to first gives both names the same data. Use copy(first) for an independent, deep copy. Cyclic structures are rejected. Library/module namespaces are read-only; exported data records can still be shared and changed.

Loops

repeat 3 times
  say "Hello"
end

for person at position in people
  say position, person.name
end

set count to 1
while count is at most 5
  say count
  set count to count + 1
end

repeat reads its count once. The count must be a whole number, zero or more. for item in items visits list items or text characters. Optional at position names the current 1-based position. Iteration uses a shallow snapshot: adding/removing list entries does not change the current traversal; changes to shared record fields remain visible.

while condition checks before each iteration. skip moves to the next iteration of the nearest loop. stop leaves that loop. They do not stop the whole application; the Studio Stop button cancels the application. Loop names remain in the current scope after a loop. To walk through a record, use for field in keys(record).

Reusable actions

make total(prices)
  give list.sum(prices)
end

say total([10, 20, 5])

Define an action with make name(parameters) and call it with parentheses. Define it before calling it. give value returns immediately; give alone returns nothing. An action that reaches its end also gives nothing. Argument counts must match exactly. Recursion works; give recursive actions a stopping condition.

Each call has local parameters and local assignments. Actions can read outer names, but set score to 10 inside an action creates/changes its local score, leaving an outer score alone. Changing a shared record/list field intentionally changes that data. if, for, while, repeat, and try do not create new scopes.

Actions capture their lexical surroundings and can be passed around or returned:

make multiplier(factor)
  make apply(value)
    give value * factor
  end
  give apply
end

set twice to multiplier(2)
say list.map([1, 2, 3], twice)

Calls wait for their result, including file access, HTTP, and sleeping. You do not need async/await syntax. Collection callbacks also run sequentially. This version has no native threads or parallel-execution primitive.

Questions

ask "What is your name?" into name
ask number "How many?" into count
say "Hello,", name

ask returns text. ask number requires a finite numeric answer. In Studio, invalid numeric input stays in the answer box so you can correct it. The terminal reports invalid numeric input as a program error. End-of-input cancels the program. For an explicit conversion elsewhere, use number("12.5").

Modules

use "helpers.plain" as helpers
say helpers.double(12)

An imported file runs once per program run. Its top-level names become fields of the namespace: actions, values, and imported namespaces. It has its own scope and shares the standard library. Imports are relative to the importing file. An import cycle is an error. Imported namespace names cannot be replaced through field assignment. A fresh run reloads modules; REPL sessions cache them until .reset.

Project files accessed through files.read and other file functions are relative to the project root, even when called from a module in a subfolder.

Handling failures

try
  set config to json.read(files.read("settings.json"))
catch issue
  say issue.message
  set config to {theme: "light"}
finally
  say "Settings step finished"
end

catch issue receives a record with message, code, source, line, and column. catch or finally is required; both are allowed. finally runs on ordinary success, failure, give, stop, and skip. An error or return in finally replaces the earlier outcome. Cancellation and execution limits stop immediately and bypass further execution, including cleanup blocks.

fail "message" raises a USER_ERROR. check condition raises CHECK_FAILED when false; an optional second expression supplies a message: check total is 10, "Expected ten".

Common codes are UNKNOWN_NAME, TYPE_ERROR, ARGUMENT_ERROR, NUMBER_ERROR, INDEX_ERROR, FIELD_ERROR, MODULE_ERROR, MODULE_CYCLE, JSON_ERROR, HTTP_ERROR, HOST_ERROR, CAPABILITY_ERROR, USER_ERROR, CHECK_FAILED, READ_ONLY, PATH_ERROR, CYCLE, LIMIT, and STOPPED. Syntax errors use PLAIN_ERROR. Cancellation (STOPPED) and resource limits (LIMIT) cannot be caught by a Plain program.

Tests

use "../helpers.plain" as helpers

test "doubling works"
  check helpers.double(6) is 12
end

Put tests in files ending in .test.plain, then use Run tests in Studio or plain test in the terminal. Test blocks are skipped during normal runs. The file's ordinary top-level code runs first, followed by its registered tests. Each test has local assignments, while reads can use file/module values. Shared data is still shared: create or copy mutable fixtures inside each test. A failing check is recorded and the next test continues. Syntax errors, cancellation, and resource limits abort that run.

Projects and tools

Start in Studio

Open Plain.html or double-click Start Plain.cmd. Studio is an offline application in one HTML file. It needs no account, server, or installation. Manual.html is this handbook; keep it beside Studio for the handbook link.

  • Select an example to explore an idea, or choose New project.
  • Use + to add a source/data file, and select its tab to edit it.
  • Set Start from to the application's entry file. Run program always starts there.
  • Format indents the active source file. Check project parses all source files and checks import paths and cycles; it does not prove types or runtime values are correct.
  • Run tests discovers .test.plain files; if none exist, it checks the active source file for top-level tests.
  • Output shows printed lines and errors. Values shows the final top-level values from the run. Project files shows source/data files, including files created by your program.
  • Rename changes the file's name; update any import paths that refer to it. Removing a non-entry file offers Undo removal until you replace the output. Choose a different entry before removing the existing entry.
  • Each edited/imported project is saved in this browser when storage is available. The Saved projects menu reopens projects. Example switching keeps edited projects. Browser storage is a convenience; Export ZIP makes a portable backup.
  • Open file adds a text file without replacing an existing file of the same name. Save file saves the active file, preserving its actual filename and extension.

Ctrl+Enter runs the project. Ctrl+Shift+Enter runs tests. Ctrl+S saves the active file. Ctrl+Shift+S exports a ZIP. Escape or Stop cancels execution, including waiting for input or HTTP. Enter continues your indentation; Tab retains normal keyboard navigation.

Move between Studio and terminal

Export ZIP includes source files, data, folders, and a plain.json manifest. Extract it, then run its folder with the terminal tools. Import ZIP opens the same project in Studio. ZIPs made by the OS with one enclosing project folder are supported when they contain plain.json. Studio handles text project files; it is not a binary asset editor.

The included task-manager project is a complete console application. It adds tasks, marks tasks complete, reads/writes JSON, uses a module, and includes tests. Its Studio data lives in the saved project and exported ZIP; terminal data lives in the project's actual files.

Terminal commands

The terminal tools require Node.js 18 or newer. No npm packages need to be installed. Open a terminal in the Plain product folder. On Windows, Plain.cmd is a command wrapper; with no arguments, it opens Studio. The portable commands below work wherever Node.js is installed.

When you select a project folder, plain.json chooses its main file; without a manifest it uses main.plain. When you select a source file, the nearest ancestor containing plain.json becomes the project root. Without one, its containing folder is the root. --root overrides that boundary, and the entry must remain inside it.

Builds

The build command is a source bundler, not a machine-code compiler. A bundled .cjs contains the parser, runtime, standard library, Node host adapter, and all imported Plain source. It runs with Node.js 18+ without the original .plain source files or npm dependencies. Builds refuse to overwrite a source file.

Data files are separate. Put required data beside the built application, or distribute a project ZIP containing the application and data. The bundled application's directory becomes its file root. Its command-line --allow-net enables HTTP; other command-line values become system.args.

REPL

plain repl requires an interactive terminal. Variables and actions persist between entries. Close a block with end to run it. Use say expression to see a value. .reset clears values and cached modules; .help shows session help; .exit leaves. A failed entry keeps assignments already performed in that session.

Editor support

The product includes a VS Code language extension folder with .plain file recognition, syntax colouring, comments, bracket matching, and indentation rules. Its README explains the local installation. Studio also works independently of an external editor.

Building the Plain product itself

node --test
node build.cjs

The first command checks the language, standard library, projects, filesystem boundaries, HTTP integration, bundled applications, ZIP round trips, and Studio event behaviour. Studio tests use an in-memory DOM; they are not visual browser tests. The second command builds the offline Studio, example catalogue, generated library reference, and standalone HTML handbook. All runtime dependencies are included; the ZIP library's notices are in vendor.

Runtime, embedding, and boundaries

Defined execution model

Plain 1.0 is a tree-walking interpreter written in JavaScript, shared by the browser and Node.js. It has dynamic types, lexical closures, function-local assignment, mutable lists/records, structural equality, and sequential, awaited calls. Each normal run starts fresh. Modules are cached for that run; a persistent session keeps its values and module cache until reset.

This release supports console applications, data transformation, scripts, file-based tools, and HTTP clients. It does not include native machine-code output, native threads, classes/inheritance, a GUI widget framework, direct database drivers, an HTTP server API, a package registry, or a language server. Lists, records, actions, modules, and JSON cover the data/reuse model implemented here. The build command packages this runtime for Node.js.

There is no supported-language claim beyond the behaviour described in the handbook and exercised by the included test suite. New features should be accompanied by changes to the parser, runtime, reference, and relevant tests. Product maturity and suitability for a particular workload need real-world use in addition to automated checks.

Numbers

Numbers use IEEE-754 double-precision floating-point arithmetic. Finite fractional numbers are supported; NaN and infinity are rejected. Integers are exact up to 9,007,199,254,740,991. For example, 0.1 + 0.2 can show 0.30000000000000004. math.round is useful for display but does not turn floating-point values into an exact decimal type. There is no arbitrary-precision integer or exact decimal type in this release.

Calls and callback invocations count execution work; algorithms such as sort and unique also count per-item steps. Large, repeated structures are bounded during display and serialization, rather than expanded without limit. File and HTTP host adapters also bound input size. Limits are practical defaults, not a guarantee of constant memory/time for every possible operation. A failed program can leave file writes or shared session mutations already performed; execution is not transactional.

Files and network

Studio file operations use the current text project. They do not read arbitrary files from the computer. Import/Open file lets the user select input; Export/Save downloads output. Entry-file deletion is protected in Studio, and Studio manages its plain.json manifest from the project-name and entry controls. Browser storage may be disabled, private, quota-limited, or cleared; portable ZIP backups are the durable format.

The terminal host resolves file paths under the project root and checks existing path components for links outside that root. Absolute paths are accepted only when they resolve within that root. Imports use relative project paths. The host has ordinary operating-system access, so these checks are application boundaries, not a hardened security sandbox against concurrent filesystem manipulation. There is no shell-execution or arbitrary JavaScript API in Plain source.

HTTP is opt-in. Enable Allow HTTP in Studio, or pass --allow-net to the terminal. Studio requests are subject to browser CORS rules. The terminal supports ordinary HTTP/HTTPS requests without browser CORS restrictions. Bodies are UTF-8 text; records/lists passed to http.send are JSON-encoded. Set a Content-Type header when the receiving API requires it. HTTP responses contain status, ok, body, and headers. Stop cancels an outstanding request; filesystem operations already in flight may complete.

Dates come from the host clock. time.now() and time.date() produce UTC ISO output; parsing supplied date text follows JavaScript Date. Random values use a pseudorandom host source, not a cryptographic generator.

Embed Plain

const Plain = require("./plain.js");

async function example() {
  const result = await Plain.run(
    'set score to 10\nsay score + 5',
    {
      sourceName: "main.plain",
      write: line => console.log(line),
      read: async (question, { numeric, signal }) => "3",
      maxSteps: 1000000
    }
  );
  console.log(result.variables.score);
}
example();

run(source, options) returns output, variables, steps, tests, passed, and failed. Output values are text lines. Variables contains top-level user names; functions are runtime values, not JSON data. Use Plain.inspect(value) for readable output and Plain.type(value) for the language type name.

parse(source, {sourceName}) returns an AST or throws a PlainError. It checks syntax without execution. format(source) validates and returns consistently indented source. catalog() returns built-in function names and minimum/maximum argument counts. resolvePath(path, from) resolves a relative project path, rejecting traversal outside the project.

createSession(options) exposes asynchronous run(source, overrides), variables(), and reset(). A session accepts one run at a time. Each invocation has fresh execution/output limits while keeping its scope and module cache. Do not change host-capability policies midway through a persistent session containing mutable application state.

Optional adapters are files with read/write/append/exists/list/remove/mkdir methods; loadModule(specifier, from) returning {id, source}; and request({method, url, body, headers, signal}) returning a response record. Input adapters return text or null to cancel. Adapters can be asynchronous. Provide an AbortSignal as signal; callbacks should also honor it to stop their own work. Host errors become readable HOST_ERROR failures.

Other options include maxOutputChars, maxItems, maxCallDepth, args, platform, test, and onTest(result). Positive integer limits are required. now and random can supply deterministic sources for testing. A PlainError includes message, code, source, line, column, and call frames. onTest receives each completed test result. Failed test checks are returned in the result; fatal errors, cancellation, and limits reject the run.
