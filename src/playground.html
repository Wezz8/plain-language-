THE WHOLE IDEA

A few words go a long way.

Start with these three.
01 / REMEMBER

Give something a name.

set score to 10
say score + 5

set saves a value. say shows it.

02 / CHOOSE

Let your code decide.

if score is at least 10
  say "Well done!"
else
  say "Keep going."
end

Ask a true-or-false question. Pick a path.

03 / REPEAT

Do a little more.

repeat 3 times
  say "I made this."
end

Repeat a block. Close it with end.

Values & maths

Use numbers like 10 or 3.5, text like "Hello", and true or false.

Maths uses + - * /. Use parentheses to group things. + also joins text.

Names start with a letter: score, first_name. Names and commands are case-sensitive. Commands use lowercase.

Questions & comparisons

ask "Your name?" into name
ask number "Your age?" into age

Compare with is, is not, is more than, is less than, is at least, or is at most. Number comparisons need numbers.

Combine conditions with and, or, and not.

Small, consistent rules

One command per line. Put text in double quotes. Start a comment with #.

Every block closes with end. Indentation helps you read; it does not change the meaning. Lists and text count from 1.

The Studio allows 1,000,000 execution steps, 100,000 output characters, 100 project files, and 5 MB per project. Export a ZIP to keep your work.

Reusable actions

make double(amount)
  give amount * 2
end
say double(12)

Pass values in parentheses. give returns a result; without it, an action gives nothing. Each call has its own variables. Recursion and returning actions work too.

Lists, records & loops

set people to [{name: "Ada"}]
add {name: "Sam"} to people
for person in people
  say person.name
end

Use people[1] for the first item. Change a field with set person.name to "Jo". remove people[1] removes an item.

while condition repeats while true. skip moves to the next iteration; stop leaves the loop.

Projects, failures & tests

use "helpers.plain" as helpers
say helpers.double(12)

test "doubling works"
  check helpers.double(3) is 6
end

Add project files with +. Imports are relative to their file. Use try, catch problem, and optional finally to handle failures. fail "message" raises one.

Test files end in .test.plain. Export your project ZIP, extract it, and run it with the included terminal tools. The handbook explains every command and library.
